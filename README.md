# DDT — Linux 客户端适配与会计辅助工作台

实验性自写适配工具与会计辅助源码。不是典当通官方产品，不是生产财务软件；公开源码齐备不代表原商业客户端已迁移验收成功。

## 目录与运行入口

- `client/`：Python部署、升级、恢复、诊断及20份Java兼容源码。商业输入和预编译JAR不公开；不是直接可安装的Linux典当通。
- `workbench/`：完整后端、TypeScript前端、页面样式、依赖、启动脚本、合成样例生成器和后端测试；从源码构建运行见 `workbench/README.md`。
- `ci/`：自写的公开SWT/GTK/WebKit合成平台探针，不加载商业客户端。
- `tools/`、`tests/`：公开分发检查、部署拒绝规则及JFR合成进程测试。

`workbench` 的演示流程是导入 → 核对 → 查看依据 → 人工复核 → 受控任务 → 辅助凭证草稿/导出。模型默认不连接，凭证不正式入账。新增文件均为可审查文本，生成的二进制样例和编译产物留在本地，不上传运行状态。

## 三类测试不能混为一谈

1. 规则/解析/审核自动测试与真实HTTP检查。
2. 真实浏览器上传、复核、下载、重启验收。
3. SWT/WebKit平台，以及另行授权的原客户端登录和业务验收。

工作台独立CI覆盖 `workbench/**`，包含规则/HTTP任务和沙箱开启的浏览器任务。平台CI覆盖客户端部署源，不只监听个别Java文件。工作流使用只读仓库权限、不持久化检出凭据、不需要模型或厂商账号，不关闭AppArmor/TLS/浏览器沙箱。**必须取得对应提交的实际运行结果才能报告GitHub Ubuntu通过，工作流文件存在不是运行证据。**

## 公开边界

禁止提交商业EXE/JAR/DLL、派生商业字节码、真实业务报表、客户数据库、会话、许可证、令牌、私钥、字体及原始业务日志。公开CI仅使用自写代码、公开依赖和合成数据。原客户端验收必须在独立授权的私有环境进行，不能把商业输入放到本仓库Release或Actions构件。

发布前运行 `python3 tools/check_public_tree.py`；该启发式检查不构成安全认证。尚未通过的正式Ubuntu安装、GDK/退出根因、真实登录与报表、模型和企业政策测试，不因本次源码迁移自动通过。详见 `SECURITY.md`。
